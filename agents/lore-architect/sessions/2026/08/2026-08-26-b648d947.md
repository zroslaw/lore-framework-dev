# Made Cursor installs marketplace-managed and shipped v43 project-scope plugin config

The session opened with a practical irritation rather than a design goal. The user wanted Lore
installed on Cursor in a way Cursor itself manages and updates, instead of the `--plugin-dir` flag
pointed at a local clone that no update mechanism ever touches. The question was whether a CLI path
existed to register and install a plugin so that Cursor would own it from then on.

Research settled it quickly and unambiguously. Cursor staff had already answered the question in
public — there is no non-interactive plugin install — and inspecting the shipped
`cursor-agent 2026.08.04` bundle confirmed it: `plugin marketplace {add,list,remove,update}` is the
entire surface, and install itself is a server-side Connect RPC (`InstallUserPlugin`). The local
`~/.cursor/plugins/cache/.cloud-plugin-manifest.json` looks exactly like an install record, holding
plugin id, marketplace slug and resolved commit, but is a downloaded cache that Cursor overwrites on
the next sync. That trap was worth naming, because it is the first thing anyone poking at the
filesystem finds and it looks authoritative. `INSTALL-CURSOR.md` was then rewritten to invert its
premise: the marketplace install became the primary path, `--plugin-dir` was demoted to framework
development, and the stale section asserting that marketplace installs were unverified was deleted
outright. That change was merged to `main` and pushed on its own, and the throwaway branch removed
at the user's request.

The session's second half began with a question that turned out to be the substantial one: whether
plugins could be configured at the project level, for every engine. Claude Code can — `enabledPlugins`
and `extraKnownMarketplaces` are valid in a committed `.claude/settings.json`. Codex cannot; the
repo-scoped equivalent is an open upstream request. Cursor's answer was not in any documentation, so
it came from reading the shipped code, which named `.cursor/settings.json` in its own error string
and revealed a self-contained entry form carrying `gitUrl`, meaning a teammate needs no prior
marketplace registration at all. The user asked for this to be written automatically whenever a
workspace is initialized, and v43 was built: a new `scripts/lr_core/plugin_config.py` performing the
merge as deterministic code, a `workspace-plugin-config` subcommand, both paths added to
`MANAGED_PATHS`, a new `workspace-status` finding S18, and 46 unit tests proven red against
`lr--v1.42.0` and green against HEAD.

Three things overturned assumptions mid-session. The first was self-inflicted: an early claim that
the marketplace could be renamed to drop its "Zroslaw" prefix proved wrong, because the prefix comes
from Cursor's UI rather than from the repo's manifest — the CLI and the UI produce differently-named
registrations of the same repository, which is why the user saw two entries. The second was a red
test that turned out to be indicting the implementation rather than itself: the idempotency check
compared canonically-rendered documents on both sides, so it could never observe that on-disk bytes
differed, and the obvious fix would have reformatted a team's entire settings file for no benefit;
writes were made minimal instead. The third came from the substitute review gate. With the lifecycle
suite and TriLens waived, three independent subagent reviews ran instead, and the correctness lens
reproduced a genuine data-loss bug in code that had already been written, tested and committed:
`open(path, "w")` truncates before it writes, so a failed write replaced a team's permissions, hooks
and env with six bytes of garbage while reporting the same tidy error row as a refusal that never
touched the file. Two further code defects and fourteen documentation gaps followed, including an
approval gate that never listed the two new writes — which would have converted an approved
`workspace-init` run into an unapproved one.

Where it landed: v43 is tagged `lr--v1.43.0` and pushed, with all four manifests at `1.43.0`, the
cache-clear footer hoisted, and the release notes recording honestly that both expensive gates were
waived and what that leaves untested. Every review finding was fixed before the tag rather than
deferred. The user's Cursor account was also cleaned of stale plugin state — a shadowing
`~/.cursor/plugins/local` symlink, an orphaned marketplace clone, and two old backup directories,
about 30 MB — and the `lore-framework` marketplace re-registered from the CLI.

Several threads remain open. The release-branch question was raised twice and never answered, so
both generated settings files track the default branch and teammates will pick up `main` between
ships. That Cursor actually reads `.cursor/settings.json` for plugins rests on code reading rather
than an end-to-end run, and is recorded as unverified in the engine profile's honest table. Merge
surfaced two framework defects worth filing: `process-merge.md` Step 0 invokes preflight without
`--workspace`, which wrote a `.tmp/lr-state/` directory inside the Lore tree, and `release-notes/42.md`
still carries its assembly-time placeholder where the gate record should be, on the tagged commit.
Finally, v43's own review fixes landed one commit past the reviewed tree, so the shipped commit
carries no reviewer verdict — recorded rather than re-reviewed.

## Learning

### lore-architect

- **What mattered:** Cursor plugin install is an account-side server operation with no scriptable
  enable step, and the local manifest that looks like an install record is a cache. Project-scope
  plugin config works on Claude Code and Cursor but not Codex, so any feature built on it must
  report the third engine's absence rather than list two and stop. Three code defects found by an
  independent review of already-tested code each generalized into a rule: a tidy error row is not
  proof the file survived; a diagnostic and its remedy must derive from one code path or the finding
  routes to a fix that cannot succeed; and adding a write to a gated procedure means updating the
  gate's template, because approval surfaces are hand-maintained enumerations that new items fall
  out of. Reading an engine's shipped bundle is legitimate evidence at a stated grade, and an
  undocumented route must stay out of a contract. Three review lenses produced almost disjoint
  defect classes, and the freeze rule was violated by applying findings while two reviewers were
  still reading.
