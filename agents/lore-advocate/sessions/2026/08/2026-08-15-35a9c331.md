# Refined and published Lore Agents README

The session began with a review of the public Lore Agents README and a search for a clearer way to
explain the product. The user wanted the opening to express a familiar burden: AI agents can be
powerful, yet people still have to supply context, refine instructions, and carry important lessons
from one session to the next.

The work progressed through several deliberately different introductions before settling on a
short positioning statement: Lore Agents are named AI specialists that learn and grow with the
user. The final framing made context maintenance part of each specialist's responsibility, named
its evolving knowledge **Lore**, and kept human direction and judgment explicit. The discarded
directions were preserved as a general public-messaging idea bank for articles, launches, talks,
social posts, marketplace copy, and future documentation.

The README then gained a concise lifecycle: create an expert for a domain, summon it through its
registered shortcut, work together, finalize the session, and return to an agent that remembers.
The setup paths, use cases, concepts, sharing model, command catalogue, shortcut guidance, directory
layout, and reference links were polished for consistency. Use cases were broadened beyond software
teams while retaining shared engineering expertise as one concrete example, and engine-specific
limitations were made explicit.

The user repeatedly pushed back when language became too technical, too bulky, or logically vague,
and also corrected an early assumption that Lore Agents were a framework delegating to separate
specialists. Those corrections established a practical advocacy rule: compare small variants first,
keep public copy visually scannable, and distinguish the framework from the named specialists
themselves.

The finished README was committed as `fac1839`, fast-forwarded onto `lore-framework/main`, and
pushed to GitHub. The registered Lore Advocate shortcut and workspace listing were committed locally
as `5e4d4c5`; the workspace has no remote, so that commit could not be pushed. Lore Advocate's
positioning and operating guidance were updated with the durable lessons from the session. Future
public materials can draw on the saved idea bank, while adding a workspace remote remains optional
if the local workspace state should later be shared.
