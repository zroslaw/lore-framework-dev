# Re-triaged the v31 lifecycle failures and closed A7's holes

The session opened with the user asking what was left for v31. The parked `lr-core` work had
been sitting on `wip/lr-core-v31` since 2026-07-25, and the recorded ship gate was a list of
six lifecycle failures from the post-A7 re-run: Codex at 6/7, Cursor at 4/7. The stated next
step was to triage those failures and then version-ship. The user's second question reframed
the session: if the lifecycle harness is a Python script, how could the same scenarios pass on
Claude and fail on Codex and Cursor?

Answering that properly meant opening the harness rather than reasoning from memory. The
Python turned out to be only scaffolding — fixture builder, subprocess driver, assertion
layer — while the system under test is a model reading prose procedure docs, so per-engine
divergence is exactly the signal the suite exists to produce. But reading the stored failure
logs to illustrate the point overturned the triage instead. Cursor's `test_05` had not failed
to stamp `lore-repo.md`; it stamped it to `30`. Cursor's `test_08` reply said "the repo
version (31) differs from the framework (30)" and showed a normal fast-path boot, meaning the
deliberately broken `lr-core` copy had never been loaded at all. Three of Cursor's four
failures collapsed into a single environment bug, and the shard was not 4/7 but
uninterpretable.

Root-causing it cost nothing. Filesystem timestamps under `~/.cursor/plugins` showed the cloud
plugin rehydrating twenty-three seconds after being moved aside and one minute forty-six
before the suite started, restoring two v30 trees at commit `11ec0df` alongside the v31
worktree link. Five live `cursor-agent` probes had been planned and were unnecessary. The
deeper finding was why A7 had not caught it: on Cursor the entire gate was an engine-side
probe asking the model which plugin root supplied its skills — a model self-report about
material a model cannot introspect. Codex had a deterministic filesystem preflight from the
start; Cursor had none, and the asymmetry was invisible because both engines nominally "had
A7 coverage."

Four fixes landed. A deterministic `check_cursor_plugin_sources()` now walks Cursor's three
plugin roots and rejects any tree whose `VERSION` differs from the tree under test — verified
against the live machine state, where it named both stale v30 trees and correctly ignored the
v31 worktree link. Per-run `framework_dir` overrides, previously exempt from identity checking
on the reasoning that they were "copies of the same tree," now get the deterministic check;
`test_08` was the only scenario handed a different tree and so the only one skipping
verification. On the plugin side, `lr-core` stopped emitting a version-skew warning that
duplicated what `version-check.md` owns — the actual cause of Codex `test_07`, where two
instructions competed and the model printed the blander one. Finally, module subprocesses now
inherit the parent's identity verdict through an `engine|realpath|VERSION` token instead of
each paying a fresh engine round-trip, which is what pushed Cursor's takeover module past its
420-second timeout.

A separate instrumentation gap surfaced while investigating Codex `test_08`. That assertion
checks whether the user was told which script failed, but `RunResult.text` came from
`--output-last-message` — the final message only — so a notice emitted mid-boot was invisible
to it, and neither the logs nor the debug dumps could settle whether the model had complied. A
one-cent probe against `gpt-5.4-mini` captured the real `--json` event schema, and transcript
capture now extracts `agent_message` items specifically, excluding tool calls and reasoning so
that `lr-core` appearing in a command line cannot pass an assertion about what the user was
told. Codex `test_08` is now decidable but still undetermined.

Two smaller threads ran alongside. The user asked for the session's diff size — 442 lines
added across seven files, of which the only confirmed v31 defect fix was eleven lines, eight
of them comment. Then, asking why `agent-boot.md` is so large, they proposed it should be
little more than "run this, and if it fails read it and follow it." Measurement supported the
instinct: the boot procedure went from 51 lines in v30 to 108 on the v31 branch, growing in
the release meant to script it away. A quarter of the file is not boot at all but the agent's
standing operating manual, and Step 2 hand-writes prose routing for fields the script already
computed, when `read_next` already solves that pattern for two of them. That was filed as a
v32 item rather than reopening the most-read procedure doc four commits from a ship.

The session ended with four commits — `03067c1`, `467b009` and `848d3fc` on
`lore-framework-dev` main, and `b824da5` on `lore-framework` `wip/lr-core-v31` — all of them
explicitly ungated, since no trilens round and no lifecycle run has seen them and `b824da5`
changes a boot-path procedure doc. Cursor's plugin directory was deliberately left untouched:
moving it is the user's call, and the last attempt showed it healing itself within seconds.
Open threads are a valid Cursor re-run once the environment is prepared, a scoped review round
over the four ungated commits, and the version-ship discipline itself. The user also invoked
plain-language, dialogue and follow-me together partway through, which was read as a stop
signal on the long analytical replies rather than a style preference.
