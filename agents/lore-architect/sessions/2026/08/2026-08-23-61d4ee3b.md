# Designed automatic daily workspace refresh for v42

The session opened with a problem the user had been living with rather than reporting: after
working in a Lore workspace for days, its repos quietly go stale. `/lr:workspace-pull` exists, but
it only runs when someone remembers to type it — and forgetting is the entire failure mode. The
user proposed hooking a refresh into the agent boot path, throttled to roughly once a day so it
would not slow every session start, with local state recording when the last pull happened and a
timeout so a network problem could not hang a boot.

Much of the machinery turned out to exist already. Preflight had pulled the agent's own repo at
every boot for some time, with a TTL stamp in `.git/lr-last-pull` and fail-fast git environment
variables. `/lr:workspace-pull` already pulled the workspace repo itself as its phase 0, dirty-
guarded, and reported how far behind it was when it skipped. Most consequentially,
`/lr:workspace-status` already diagnosed every condition the user described wanting a new cleanup
command for — dirty managed files, unpushed commits, off-branch repos, commits waiting upstream —
with each finding naming its own fix. The feature therefore shrank from "build a refresh system"
to "widen an existing TTL from ten minutes to sixteen hours, widen its scope from one repo to the
workspace, and make the existing diagnosis run on its own."

The design settled through a long back-and-forth over the state file. It began as a JSON blob with
per-repo results and a finding-memory, was cut to a single bare timestamp, then re-grown for
readability once the user asked for it, and finally landed as an extensionless file holding
`key: value` pairs parsed by the framework's own `parse_frontmatter` — which prompted a further
decision to extract that function's inner loop as a reusable `parse_yaml_subset`, so descriptors
and state files would share one parser instead of two. Along the way the user pushed back sharply
on the assistant presenting balanced menus instead of recommendations, which changed how every
subsequent decision was put.

A first design document was written to `workdir/draft-workspace-auto-refresh.md` and then reviewed
by three cold-context Sonnet subagents booted as lore-architect — a lean-design lens, an
implementation-fidelity lens briefed as the engineer who must build from the document alone, and
an adversarial runtime-failure lens. The reviews were harsher than expected and largely correct.
All three independently found that the document's JSON contract invented fields the scanner does
not emit and would have duplicated prose that `docs/workspace-status.md` owns — violating a rule
the document itself stated two paragraphs earlier. The failure-mode lens found that the
concurrency guard did not actually exclude anything across processes, and worse, that a killed
refresh would leave a fresh timestamp and silently disable the feature for a full sixteen hours,
which is precisely the failure the feature exists to prevent. The fidelity lens caught a factual
error the assistant had asserted as load-bearing evidence: that `scripts/workspace-pull` accepts no
arguments, when it takes a positional workspace directory. Every claim was verified against source
before being accepted.

Revision 2 incorporated the findings — a lock file with exclusive create and stale reclaim, the
scanner's real `{id, severity, data}` shape, results derived from `git rev-parse HEAD` snapshots
rather than parsing coloured terminal output, process-group kills so a timeout would not orphan
backgrounded git children, and an explicit never-raise acceptance bar after confirming that
`cli.py` wraps all of `cmd_preflight` in one `except Exception` that routes every boot into the
Manual Boot Procedure. A subsequent lean pass over revision 2's own additions found four
redundancies it had introduced while fixing things: two overlapping enums that disagreed on a
shared value, a `running` state duplicating the lock file's existence, a `reason` value duplicating
a list, and a lock file storing a timestamp the filesystem already keeps as mtime.

Two design questions were closed rather than deferred. Whether to skip dirty child repos was
decided against — dirty is the normal state of a repo being worked in, so guarding on it would make
the most-used repos permanently stale while nagging daily about work-in-progress; the resolution
was to report which repos were pulled and which were dirty when pulled, without asking the user to
act. The second was subtler: a fresh workspace would have tried to clone every declared repo inside
a ninety-second budget and timed out mid-clone on a user's very first boot. Short-circuiting on
"is there a state file" would have broken the documented delete-to-force-refresh gesture, so the
short-circuit was keyed on the real condition instead — the scanner's S6 finding for declared repos
missing from disk. The refresh now never clones.

The session produced design only; no framework code was written. The document was committed to
`lore-framework-dev` as `f09ed9a` and remains the handover artifact for implementation, targeted at
v42 and cache-affecting. Three open questions remain, all low-stakes: whether `/lr:pull-lore`
should reset the workspace stamp, whether `workspace-pull` should become TTL-aware to remove one
redundant pull, and whether sixteen hours is the right interval — a judgement call rather than a
measurement, left adjustable via `--workspace-ttl`. The gate decision for the eventual ship was
deliberately left to ship time, with the document noting that this change lands in the boot hot
path where v40 shipped ungated and carried five defects to users.

## Learning

### lore-architect

- **What mattered:** User feedback that presenting a balanced menu instead of a recommendation
  reads as absence of judgement and costs trust — state the view and its reason, then at most one
  question; `/lr:style follow` gives the user the direction, not silence on the substance. Two
  design rules named while designing the refresh: a guard keyed on a *normal* state silently opts
  out the feature's heaviest users, so report rather than guard when the risk is "the user did not
  know"; and short-circuit on the real condition, never a convenient proxy, because the proxy fails
  exactly where a user acts deliberately. Fix rounds introduce a second defect shape beyond context
  errors — **redundancy**, where the new mechanism re-expresses a fact an existing one already
  carried — caught by a cheap diff-scoped "what does this now say twice?" pass. Two verified facts:
  a negative grep proves the searched *pattern* absent, never the capability; and
  `lr_core/workspace_scan.py` has no dirty-child-repo finding at all, while `workspace-pull` phase 4
  fast-forwards children with no dirty check.
