# Adopter Command-Surface Curation

The Lore command surface should be organized around an adopter's workflow, not exposed as an accumulated flat catalog. A newcomer should be able to see the first path: load an agent, recall as needed while working, collaborate when needed, finalize, then diagnose or refresh.

Progressively disclose the rest:

- daily workflow — boot, recall, finalize
- collaboration — attach and consult
- maintenance — pull, check, doctor
- setup — workspace/repo/agent creation and registration
- advanced modules — Lore Beings, Dark Factory, worktrees, takeover
- style controls — `/lr:style` (single skill; v35 removed the former `plain-language` / `dialogue` /
  `follow-me` commands)

Run an inventory of every skill and decide whether to retain, rename, combine, move behind progressive disclosure, or retire it. The goal is clarity for a new adopter, not command-count minimization. The installed skill directories remain the ground truth until this curation becomes a shipped change.
