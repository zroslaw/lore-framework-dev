# Validated and shipped Lore Framework v33

The session opened with the v33 release nearly ready to ship. The requested gate was explicit: run unit and lifecycle coverage in engine order—Cursor with Composer 2.5, Codex with gpt-5.4-mini, then Claude Code with Haiku—repair any real issues, rerun failed cases, and push only when green.

The work exercised standard and Keeper lifecycle suites across all three engines, then reran the full deterministic unit suite. The release work improved engine detection and boot guidance, shortcut freshness checks, and lifecycle-harness identity handling. It also corrected fixture scope so the dry-run test verified non-mutation instead of spending an engine run narrating historical migrations.

Several failures clarified the boundary between framework behavior and test environment state. Cursor could append prose to an identity version line; Codex needed special handling for a documentation-driven broken-script fixture; and Claude could rehydrate a stale plugin tree that masked the local checkout. The gate now treats installed-plugin identity as test evidence, and the forced fallback scenario makes the required user notice observable in final-only engine transcripts.

The release landed with all unit tests and all standard and Keeper lifecycle suites green after their relevant reruns. `lore-framework` and `lore-framework-dev` were committed and pushed to their `main` branches. The session’s durable lessons were merged into Lore Architect’s lifecycle, identity, and transcript-evidence lore.
