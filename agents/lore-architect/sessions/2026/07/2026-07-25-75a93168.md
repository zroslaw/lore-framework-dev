# Cursor usage auto-retrieval investigation

The session opened with the user booting Lore Architect and asking whether coding engines can automatically query usage statistics — plan quota, session context fill, and per-turn token counts. The investigation quickly separated three metrics that community tools often conflate: monthly plan quota (subscription allowance), live session context percentage (how full this chat's window is), and per-turn token usage from the last API call.

The substantive work mapped what is scriptable today on Cursor. Plan quota is reachable via an undocumented `GET cursor.com/api/usage-summary` endpoint, but only when authenticating with a `WorkosCursorSessionToken=<sub>::<jwt>` cookie built from the local `state.vscdb` access token — bare Bearer auth returns 401. Session context percentage is exposed only through the CLI statusline hook (`context_window.used_percentage` on stdin), configured in `~/.cursor/cli-config.json` (not project `.cursor/cli.json`, which rejects `statusLine`). Headless `cursor-agent -p` does not invoke the statusline; the IDE context ring is manual-only for agents.

A draft unified probe landed in `workdir/cursor-cli-usage/` (`lr-cursor-usage.sh`, `lr-context-statusline.sh`, README). Earlier PoC scripts in `.tmp/lr-context-poc/` were superseded. The user's live Pro account was verified at roughly 38% total plan usage with API tier at 100% for the Jul 5–Aug 5 billing window.

The session landed with a new lore topic `cursor-usage-auto-retrieval.md`, cross-links from `cursor-engine-capabilities.md` and `lore-context.md`, and finalize completing reflect/merge/summarize/archive. Open follow-ups include a `/lr-cursor-usage` skill wrapping the workdir probe and cross-engine quota retrieval (Claude OAuth, Codex app-server) — neither was in scope for this finalize.
