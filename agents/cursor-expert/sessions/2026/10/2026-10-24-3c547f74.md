# Recorded subagent and peer-agent limits

The session opened with a request to spawn three Composer 2.5 subagents and keep them alive. The user then asked whether those workers could sit idle, whether resume kept their context, whether they could be destroyed, and whether two of them could greet each other. The last questions asked whether the communication limit belonged to Cursor or to the model, and how a team of agents should talk.

The parent agent spawned three background subagents and told each to sleep. One of them returned a status line and ended its run, so the parent resumed it. A later interrupt stopped all three. Resume of the first id brought back the same thread: it remembered the sleep and the stop. There was no tool that deleted an agent id. Two new subagents, named Alice and Bob in the prompts, exchanged hellos only because the parent copied each reply into the next prompt.

The direction changed when a long sleep failed to park a worker. A subagent run ends when it returns a final message, so an idle loop is not a standby process. The user then asked for the right team pattern. Docs and a Cursor staff forum reply showed a hub: Task subagents answer the parent, a Project coordinator relays between workers, and Agent SDK peer connections join separate deployed agents. Composer 2.5 was not the constraint.

The user asked to boot cursor-expert and save the session. Finalization booted that agent as host, wrote two reflection notes, and merged them into existing lore: subagent reach, SDK peers, the Project hub, designer notes, and the working context. No guest agents were attached.

Nothing in the product design was left open. The saved facts are ready to commit with this summary. A later session can use the same lore when someone asks how Cursor agents coordinate.

## Learning

### cursor-expert

- **What mattered:** Task subagents return one final message to the parent. Parallel siblings share no transcript, and a model choice such as Composer 2.5 adds no sibling channel. The parent copies any cross-sibling message; resume continues that same subagent; a background run ends when the subagent returns. Agent SDK peers are separate full agents (local co-host or a team deployment slug), called with ask, check, and call_tool. They do not relay editor Task subagents. A Project stays a coordinator hub: the coordinator relays, and workers do not message each other.
