# Mapped Codex multi-agent session boundaries

The session began as a practical exploration of Codex subagents. It established that child agents in one chat can exchange direct messages through the collaboration channel, while the user also explored how many workers the desktop harness can keep active and how worker cards appear in the app.

The work exposed an important boundary. A separately launched Codex CLI session could not message the Desktop chat's child agents, because each belongs to a separate multi-agent session tree. A persistent CLI session could instead create its own children and let them exchange greetings; an `--ephemeral` CLI run could not create children in the test because it lacked stored rollout context.

The session then distinguished the Codex Desktop limit from the Agents API configuration. The current Desktop chat exposed a fixed cap of three active children and no user setting to raise it. The official Agents API documentation instead provides `max_concurrent_subagents` at session creation, so an application can request a higher limit through its own API-backed session.

The result is durable product guidance rather than a general claim about all future builds: same-tree collaboration is direct; independent chats need a coordinator or shared external system; and local CLI observations should be rechecked after a Codex update.
