# Shipped v47 after a full three-engine lifecycle gate

The session opened with the user booting the lore-architect and asking where the v47 release stood. The repository showed `lore-framework` main still at v46 with the v47 work, finalize participant revision, finished and polished in a separate worktree but never merged, tagged or published. The user then asked for the full lifecycle suite to be run on Claude Code, Codex and Cursor against that worktree, for any findings to be fixed, and explicitly not to run the quality benchmark or a TriLens review.

Running the suite meant working around the plugin-identity check, which refused Codex and Cursor because installed copies of the plugin outranked the worktree. Rather than repoint the user's real engine configuration, the Codex and Cursor arms were run under a throwaway `HOME` with a repointed Codex marketplace and Cursor's keychain linked in. The deterministic modules were green first. The lifecycle run then produced a spread of red scenarios on the cheapest model tiers, which were triaged and re-run on stronger models: most were weak-model or assertion-formatting flakes, one (`test_27`) was a genuinely stale scenario still driving the `lr:workspace-status` skill that v45 had removed, and a few were not touched by v47 at all (Claude `test_09` fails identically on v46; Codex style `test_30`). Both new v47 scenarios passed on all three engines.

Along the way the Codex arm exposed that the harness default model `gpt-5.4-mini` is unsupported on a ChatGPT-account login, that `gpt-5.5` needs a longer run timeout, and that the account's usage limit eventually cut the last re-runs short, leaving Codex boot `test_05` unconfirmed. An early explanation for that failure (a missing git identity in the temporary HOME) was stated too confidently and was falsified by the next run, and the user was told so. The user also raised, mid-run, that token usage was nearly exhausted, which prompted a stop to the lowest-value re-runs.

Two decisions changed the shipped scope. The user asked for the TriLens lifecycle module to be excluded from the default matrix and run only on explicit request, which was implemented in `run_matrix.py` and the test README, and for three skills (`wait`, `df-repo-init`, `df-ula-file`) to be hidden on every engine while keeping their procedure docs and the `lr-wait` server. After that the release notes were updated with the real gate dispositions, the skill removal was committed, and `lore-framework` main was fast-forwarded to `17ba607`, tagged `lr--v1.47.0` and pushed. The worktree and branch were removed, no other stale worktrees or branches existed, and the temporary HOME holding a copied auth token was deleted. The lifecycle test fixes were committed and pushed to the dev repo.

The release landed with an honest gap: the lifecycle result belongs to `79b26a4`, and the skill-hiding commit that became the tag came after it, checked only by the plugin check, the Cursor-mirror check and five deterministic modules. The remaining open threads are Codex `test_05` (also red before v47, cause unknown), Codex style `test_30`, the stale `gpt-5.4-mini` default, and a possible `LR_HOME` override so isolated-engine runs need no manual setup.
