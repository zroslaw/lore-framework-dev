# Shipped v44 and recorded its gate gaps honestly

The session opened as a routine boot of the lore-architect, which immediately turned into
housekeeping: the agent repo was stamped at framework version 42 against an installed 43, so the
boot-time upgrade ran, applied the release-notes-only v43 step, stamped the repo and pushed. The
user then asked a single question — what the status of v44 was — and the answer set the agenda for
everything that followed. v44 existed as roughly fifty uncommitted files in a worktree, fully
built and partially gated, with nothing committed and no tag.

The user's next few turns were about whether that state was good enough to ship. It was, with one
honest qualification worth stating plainly: the deterministic suite, `/lr:check`, dogfooding and
the Claude lifecycle run all supported the claim that v44 did not harm existing quality, but the
Codex and Cursor lifecycle arms had never run, and v44 changes files both those engines read —
`scripts/lr_core/preflight.py`, `workspace_scan.py`, both engine profiles, and the Cursor skill
mirrors. The user acknowledged that, declared the one remaining in-scope defect a known bug, and
asked for the release to go out.

Shipping surfaced the session's sharpest finding. `release-notes/44.md` was complete on what
changed and carried no Verification section whatsoever — no gate dispositions, no statement of what
remained untested, no known limits. The full and accurate gate record had existed the whole time,
in the agent's own lore. Every discipline about naming gate dispositions had been satisfied in the
wrong artifact. That section was written before tagging, and the release notes' own `540 tests`
claim was re-measured against the shipped tree rather than copied forward; it came back green at
540 across 15 modules. Four mechanical checks were also run by hand at push time, three of which
already exist as `/lr:check` items and one of which — Step 0 presence across all 33 skills, the
release's headline claim — has no check at all.

v44 then went out: feature commit `c56eb60`, merged no-ff into `main` as `26a9dac`, tagged
`lr--v1.44.0`, both pushed, with the version-history backfill and the draft-to-shipped flip of
`skill-announcement-convention.md` landing in the dev repo alongside the test changes that back the
release.

Two plot twists arrived late. First, a `/lr:style` invocation revealed that the engine dispatches
skills from the `1.42.0` plugin cache while the entire session had booted from `1.43.0` — the cache
holds several versions at once, and resolving `<framework-root>` by taking the highest version
number derives an answer the engine had been printing all along. Second, during finalization
itself, merge's own Step 0 was found to have written a stray `.tmp/lr-state/workspace-refresh` inside
the agent's `reflections/` directory, because that step passes no `--workspace` and the flag
defaults to the current directory. That one is a genuine shipped bug with three effects: litter, a
defeated 16-hour TTL, and escape from the workspace-anchored `/.tmp/` gitignore line.

The release is out and the record is honest about what backs it. Open threads: Codex and Cursor
lifecycle coverage still needs local install changes; the Step 0 convention has 33 sites and no
mechanical guard; the `being.md` versus `create-agent.md` registration contradiction ships as a
documented known bug; and the workspace-refresh state-root bug is filed for a fix in the resolver
rather than at its call sites.

## Learning

### lore-architect

- **What mattered:** A gate record kept in lore is not a gate record in the release notes — v44's
  notes had no Verification section at all, and an accuracy audit passes cleanly over an absent one,
  so presence must be audited before accuracy and the notes written before the lore copy. Claude's
  plugin cache holds several versions simultaneously, so resolving `<framework-root>` by highest
  version number silently boots off a tree the engine never dispatches, and the resulting wrong
  `VERSION` is what a boot-time upgrade stamps into a repo. A ship that makes a countable claim
  about the whole tree ("all 33 skills do X") earns a mechanical check before the release notes may
  assert it, because a hand-verified assertion over 33 sites holds for exactly one commit.
- **Lore changes:** `lore/claude-plugin-cache-holds-multiple-versions.md` — created, the
  multi-version cache trap as a Claude engine fact; `lore/a-release-record-goes-stale-while-you-fix-it.md`
  — updated with the presence-before-accuracy rule; `lore/consistency-checks.md` — updated with when
  a ship's claim earns a check, plus two candidate checks; `lore/feedback-too-many-words.md` —
  updated with the verdict-not-briefing signal; `lore/workspace-auto-refresh-design.md` — updated
