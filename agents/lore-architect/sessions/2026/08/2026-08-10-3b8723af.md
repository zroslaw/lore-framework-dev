# Made Codex shortcuts workspace-local, then TriLensed all of v37

The session opened on the unshipped v37 release and a question that sounded like
housekeeping: did the new workspace layer account for project-level engine directories such as
`.claude/` and `.codex/`? Answering it required stating where each engine keeps its per-agent
shortcuts, and the framework's own answer for Codex — the user's home directory, unreachable by
git — turned out to be an assumption that had hardened into shipped prose across four documents.
Three model-free probes with `codex debug prompt-input` on `codex-cli 0.142.5` established that
Codex discovers skills under the git root of the session's working directory as well as under
`~/.codex/skills/`. The limitation was the framework's own choice, not the engine's.

On that basis the user asked for the change to be folded into v37 rather than deferred:
registration now writes `<workspace>/.codex/skills/lr-<agent>-agent/SKILL.md`, the path joins
`MANAGED_PATHS` so `workspace-push` publishes it, `shortcut_inventory` gained a fourth key for the
legacy home location, and finding S15 was repurposed from "repos missing a Codex shortcut" to
"Codex shortcuts still in the home directory". A new `migrations/37.md` relocates them with an
ownership check and a verify-before-delete rule, because `~/.codex/skills` is user-global and a
same-named shortcut may belong to another workspace entirely. Sixteen unit tests gave
`workspace_scan.py` its first deterministic coverage. Lifecycle tests, quality tests and a TriLens
round were all waived at the time.

The user then reversed that waiver and asked for a TriLens over the whole release. It ran three
rounds — the ceiling — with nine cold lenses: script-to-doc equivalence, destructive safety and
cold-user coherence; then fix verification, executor simulation and installed-base upgrade; then
shell signal safety, the finding set as a system, and documentation coherence after twenty
piecemeal patches. Twenty-eight findings: twenty-five applied, one accepted, two declined. The
release body held up — one genuine pre-existing defect in eight hundred new lines of scanner, a
dirname-keyed map that silently dropped one of two colliding declarations and then checked a
child's origin against a URL the user had never cloned from.

The plot twist was that rounds two and three each caught a defect introduced by the *previous
round's own fix*. A round-one change meant to stop Ctrl-C leaving a half-written clone could
instead delete a completed one — a recoverable annoyance traded for data loss. Round two's
replacement needed a predicate distinguishing a finished clone from an interrupted one, which
round three showed cannot be got right; the third version has no predicate at all and is shorter
than both attempts. Separately, a round-one doc edit that deferred "the Agents-section step" to a
single pass skipped a bundled sub-item ensuring the `CLAUDE.md` import stub, silently reopening the
whole-engine outage v37 exists to close. Both defects were the author's, both were introduced while
fixing something else, and neither was visible from the finding that prompted the fix.

One reviewer's blocker did not survive checking. It arrived with an empirical claim — that the
signal handler dies at its own process-group kill before reaching cleanup, verified on bash 3.2 —
and did not reproduce locally across three process-group configurations, including the one named.
The hardening was kept because it removes a timing dependency for free, but it went in as
hardening rather than as a confirmed fix, and the commit message says so instead of repeating the
claim. Two of nine lenses also went idle without reporting; a single follow-up ask produced both
reports, one containing the round's blocker.

Work landed as four local commits across two repos, none pushed and none tagged, per standing
instruction: `4c0dd2c` and `7527527` in `lore-framework`, `f505e8b` and `ceef2eb` in
`lore-framework-dev`. The deterministic suite is green at 387 tests, up from 379. Closing exchanges
turned on what the review had and had not proved: nine reviewers read these procedures and none
executed them, so the release's real remaining gap is not a missing finding but the absence of a
lifecycle run, of unit coverage for S1 through S14, and of any dogfood of this workspace onto v37.

Next steps, in the order agreed: run the lifecycle suite, converge this workspace onto v37
(it still carries a marker-format `AGENTS.md`, no `CLAUDE.md`, and eleven Codex shortcuts in the
home directory), bump `lore-framework-dev/lore-repo.md` from 36 to 37, and only then ship. A fourth
TriLens was declined in favour of running it later over whatever execution disturbs.
