# Reviewed v46 Tier A as a subset and held it pending Tier B

The session opened on a wait. The user asked that nothing begin until a finalization running in an
adjacent session had completed, and specifically that the lore-architect not be booted until that
session's agent registration was done. A watcher was armed on the workspace repo; when the user
confirmed the other session had finished, `lore-framework-dev` was verified clean at
`a7288a3 Finalize session a998a63d` and the architect booted. The intended work was the v46
lore-sync-hardening plan — the framework's long-standing problem that agent repos accumulate
unpushed commits, diverge, and then fail every subsequent boot pull while nothing reports it.

Implementation started on Tier A, the four changes a decision earlier the same day had cleared to
land with "no further review" after nine reviewer passes found nothing against them: C5 keying the
workspace refresh TTL on `last-success`, C6 inverting `workspace-pull`'s Phase 0, C7 adding a
§ Tooling: Git Safety section to `conventions.md`, and C4 in bare form (a new finding R16 reporting
a repo's ahead/behind counts, with no marker). C5 and bare C4 were written and the CLI help text and
`preflight.py` docstring updated alongside them. The user then interrupted and asked whether the
design was actually agreed, which turned out to be the right question: implementing had already
surfaced four seams the spec did not resolve, the sharpest being that C7's rules cite a
`publish-lore.md` that only Tier B creates.

The work was reverted to a clean tree and a fourth review round was run instead, scoped to Tier A
alone. Lens choice mattered here. Three prior rounds had spent eleven lenses, all analytical and all
asked of the whole document, and had stalled at 14 → 16 → 13 findings. Round 4 kept the model tier
and changed the unit and the question instead — Tier A as a shippable artifact, "does this ship on
the tree that exists?" — and picked three situational lenses: tier boundary and partial ship, the
shipped call graph rather than the spec's prose, and the installed population's first boot after
upgrade. Verdicts came back SHIP-WITH-FIXES, SHIP-WITH-FIXES and BLOCK, with thirteen findings that
triaged to six real ones.

Two were not cosmetic. C5's flat 900-second retry floor was wrong in both directions at once: too
weak, because real boots are hours apart so the floor never engages, turning one bounded refresh per
sixteen hours into one on every boot for any workspace that cannot sync; and too strong, because
applied unconditionally it voids the documented `--workspace-ttl 0` contract that two shipped tests
pin. And C7 would have landed a convention forbidding `git add <directory>` while `docs/finalize.md`
line 83 is literally `git -C <repo> add agents/`, fixed only by a Tier B change. The R16
findings-catalog row was separately found to contradict its own spec, offering a `merge && push`
remedy that § 4 explicitly calls unsafe. All six were amended into §§ 7, 8, 10, 11 and 12 in place
rather than recorded only in the ordering section, and a further single cold reviewer over those
amendments returned ten more findings, nine applied — one of which was a self-inflicted
contradiction left standing in § 14 while fixing something else.

The direction then changed on a question from the user: why implement Tier A before the design is
finished at all? The spec's own answer was instrumentation — bare R16 would measure how often
divergence actually occurs and decide whether Tier C is worth building. That argument did not
survive scrutiny, because R16 in Tier A would count divergence under exactly the regime Tier B
removes, so its numbers expire when the cure lands. Set against a user-facing warning whose wording
and severity the tier seams had already forced two rewrites of, the case for shipping first
collapsed. The decision taken was to design Tier B to completion and decide Tier C before shipping
anything; Tier A is held rather than cancelled.

Nothing was shipped and no framework code changed — `lore-framework` ends the session clean at
`90da5b3`. What landed is the amended spec, an updated standing improvement list, and the lore
below. Two unrelated dirty working trees were deliberately left untouched throughout: another
session's finance-keeper registration in the workspace repo, and a health-advisor merge in
`lore-agents` produced by a background teammate that reported in mid-session.

Next: the deep unconstrained cold review of Tier B, which was already mandatory and is now the
critical path, followed by a Tier C decision. Only then does the ship order get settled. The § 14a
ordering claim and `non-convergence-diagnose-before-reviewing-again.md`'s Tier A guidance were both
corrected this session and should not be re-derived from their earlier form.

## Learning

### lore-architect

- **What mattered:** Tiering a stalled spec is itself a change, and the carved-out subset has never
  been reviewed as a subset — a Tier-A-only round produced six findings, including a BLOCK, that do
  not exist in the whole document. "Ship the detector first for the data" only holds when the cure
  preserves the population being measured, which it did not here. When correctness lenses stop
  yielding, change the unit and the question rather than the rigor. An interval constant must be
  priced against the real event cadence *and* against any configured knob it silently overrides.
- **Lore changes:** `lore/tiering-a-reviewed-spec-creates-unreviewed-seams.md` (created),
  `lore/a-detection-tier-must-outlive-the-cure-it-measures.md` (created),

  change-the-unit lesson in place rather than creating a near-duplicate),
