# Resumed parked v31 `lr-core`, ran a review round, applied the fixes

The session opened by booting as lore-architect and picking up the parked v31 `lr-core` work — a
deterministic substrate script plus doc rewiring that had been implemented, twice trilens-reviewed,
and then deliberately held uncommitted on `wip/lr-core-v31` after a rough prior session. The user
asked what was left before v31 could ship; the answer, per the parked lore topic, was two missing
regression tests, a widened trilens round (to cover a 2026-07-26 literate-accelerator addendum that
predated this session and had never been reviewed), the full lifecycle suite, and then commit+push.
The user then asked to bring the parked, compressed `docs/trilens-loop.md` into view, and — after
switching the session's default model to Opus — directed the session to do the regression tests and
the review, using the parked v31-compressed trilens instruction rather than the shipped v30 one, but
explicitly to stop short of the lifecycle suite and the ship itself.

The session added the two missing regression tests to `tests/test_lr_core.py`, verifying each by
mutation (reverting the underlying fix and confirming the new test failed) rather than trusting a
pass. It then ran one trilens round — three cold, independent subagent lenses (hand-executor,
adversarial correctness, corpus coherence) — deliberately scoped to the entire v31 surface across
both repos rather than the narrower delta the old resume plan described, so the reviewed state would
equal the shippable state. All three lenses returned SHIP-WITH-FIXES with no BLOCKERs, but surfaced
five HIGH findings and a long tail of MEDIUM/LOW ones. Each was independently reproduced against the
real worktrees before being fixed: `pull_repo` was found to silently fast-forward the *enclosing*
git repository (and drop its TTL stamp there) whenever a lore repo was merely a subdirectory of a
larger git repo rather than its own git root, while still reporting the inner path — a mutating
operation attributed to a place it never touched, under exit 0. A second class of bug traced to the
unrunnable-git sentinel colliding with subprocess's own negative-returncode encoding for signal
deaths, silently turning a killed `git` process into "not a git repo." Several more followed: a
non-ASCII lore-topic filename read as never committed because of git's default path-quoting; `031`
and `31` compared as a version skew rather than a match, which would have told a user to reinstall an
already-correct plugin; a UTF-8 BOM silently voiding an entire frontmatter block; an exit-2 fallback
payload that was shape-identical to a determinate `ok:false` whose documented handling is the
opposite; and the Manual Boot Procedure's hand-executed path rejoining the numbered boot steps one
step too late, silently skipping the step that reads `version-check.md` and `teammate-conventions.md`.

The most structurally significant finding was that the literate-accelerator pattern itself — where a
script's own comments are the fallback spec instead of a companion doc — had no floor for the case
the pattern cannot self-serve: the script file being missing rather than merely broken. The Script
Fallback Contract's failure triggers covered a bad exit, a missing interpreter, unparsable output —
but never "the artifact I'm supposed to read for the fallback is itself gone." That gap was written up
as a durable lesson, both in `docs/conventions.md` (an explicit floor: recover from git history or
another install, else say plainly what cannot be done) and in lore, generalized as: when a design
removes a redundancy, audit the case the redundancy used to cover. Release notes were also found to
contradict their own body (the accelerator's definition still read as the pre-addendum framing forty
lines before the addendum's own section), and to omit any mention of the `docs/trilens-loop.md`
325-to-15-line rewrite entirely — both were fixed, along with a missing `## Verification` section that
now states plainly what has and has not been gated.

One finding was deliberately not auto-applied: `docs/engines/cursor.md` still names `trilens-loop.md`
as the carve-out where subagent independence is the semantics, but the compressed doc no longer
states any engine-binding instruction or the "no subagent mechanism → stop" rule that the carve-out
depends on. Because the trilens-loop compression itself was recorded as a deliberate, repeatedly
user-pushed-for decision — and re-expanding any part of it was explicitly flagged in lore as needing a
fresh ask rather than a default reversion — the session surfaced this gap instead of quietly patching
around it, and left it as an open decision for the user. The test suite grew from 38 to 51 tests, all
green, and `scripts/lr-core` was verified byte-identical after each mutation-testing pass.

Partway through round 2 — three fresh cold reviewers spawned to re-check the fixes with the ledger
from round 1 in hand — all three subagents failed immediately on the account's monthly spend limit,
before doing any real work. The user, separately, asked what had driven this session's context usage;
the answer was mostly the long verbatim reports returned by the round-1 subagents plus the session's
own direct file reads and verification commands, not the subagents' own (separately budgeted)
reasoning. Rather than retry round 2 once the spend limit clears, the user explicitly chose to stop
the loop where it stood: address only the round-1 findings already in hand, and do not run a further
review round at all. The session complied immediately and moved to closing out round 1's fixes rather
than re-litigating whether more rounds were warranted.

The session ends with both worktrees (`wip/lr-core-v31` in `lore-framework` and `lore-framework-dev`)
still fully parked and uncommitted, exactly as before session start except for this session's fixes —
nothing was committed or pushed, and the lifecycle suite was not run, matching the user's explicit
