# Revised finalize participant revision draft to best-fit host

The session reopened the draft design from 2026-10-03 for `/lr:finalize` participant revision,
intended for v47. In that draft, finalization adds agents whose role fits the session's knowledge,
and the booted agent stays host unless none of the knowledge plausibly belongs to it. The user
wanted to change the host-guest model. Over a short dialogue they settled three decisions:
finalization should pick the *best* host by matching the session's topic and results against each
agent's role, with the booted agent keeping close calls; additions stay uncapped, but the design
must say plainly that every finalizing agent costs time and tokens; and confidentiality should
remain a short guard, not a large part of the design.

The user then asked for the usual multi-round review cycle, first over the design and then over the
implementation spec, with minimalism and future extensibility as the priority. The design went
through three rounds of three cold reviewers each, with lenses including minimalism, a
literal-executor walkthrough of concrete sessions, a claim audit of each fix round, end-to-end data
flow through the real phase docs, and a post-fix consistency audit. The spec then went through
three more rounds: minimalism, fidelity to the design, implementability against the real framework
and test files, and literal execution of the patched `finalize.md` text alone. Every round ended
SHIP-WITH-FIXES or SHIP, with no blocker or high finding after the first design round. Both drafts
in `workdir/` were updated, and the design's review log records every applied and declined finding.

Two things shifted along the way. The close-call rule had no executable test at first, so it became
concrete: the booted agent is replaced only when both the main topic and the main result lie in
another agent's role. The confidentiality guard kept producing new leak findings round after round,
because each patch opened a new seam. It finally collapsed into the coarsest fail-closed form: if a
confidential repo is in use, revision changes nothing (and with nothing booted, finalize stops).
Reviewers also disagreed twice on whether a demoted booted agent's repo would still be committed.
Reading `finalize.md` settled it: the "No empty commits" invariant would skip that repo, so the
sentence requiring the commit stayed.

Both drafts are revised and ready for the user's review; nothing in `lore-framework/` was changed,
and v46 remains current. The final round's local wording fixes were not reviewed by a further
round, so the implementer should re-read spec §1a against the patched `finalize.md` once. The next
step is implementation as v47 once the user approves.
