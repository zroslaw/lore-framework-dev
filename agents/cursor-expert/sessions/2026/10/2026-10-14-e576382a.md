# Created cursor-expert and mapped Cursor's product family

The session created the first real knowledge for cursor-expert, a new agent in this repository and a sibling of claude-expert. Its role file already existed, with only a stub context. The goal was a complete, sourced map of Cursor's products from the user's side, at least as wide as claude-expert's coverage of Claude, and deeper where Cursor has its own mechanisms. Particular weight went to one question: can a remote MCP server (HTTPS, OAuth) be used from the Cursor editor, the CLI, cloud agents, and the web and mobile surfaces, and with which plan, auth, and MCP features?

The agent booted, studied all of claude-expert's Lore as the template, and read the Lore framework's Cursor engine profile and lore-architect's Cursor notes for context only. Research then ran against primary sources. The full docs index at cursor.com/llms.txt was downloaded as raw markdown pages, and the release notes, pricing page, changelog, blog, and a few x.ai news pages were read for dates and plans. The result is a root context plus four areas with nineteen topics and two root topics: apps and surfaces (editor and Agents Window, CLI, cloud agents, self-hosted machines and Remote Control, mobile and web, integrations and APIs, Bugbot and Automations, Grok Bot), the extension platform (MCP, remote MCP per surface, plugins and marketplaces, skills and subagents, hooks, admin controls), memory and personalization (rules, AGENTS.md, other persistent context), plans and models, Lore compatibility on Cursor surfaces, and notes for agent-framework designers. Every fact carries a check date, a source, and a label.

Several findings changed the picture compared with older knowledge. Cursor is now part of SpaceX, its own frontier models are Grok models co-trained with SpaceXAI, and since 2026-10-12 the pricing page sells The X Subscription while the docs still describe the older Cursor plans, so plan answers must name the plan family. Cursor has no general memory feature for its coding agent any more; rules and files carry persistent context. Grok Bot fills the role that Cowork fills for Claude. Some official pages disagree, most visibly on SSE support for MCP servers in cloud agents, and these conflicts are recorded rather than resolved by guesswork. Midway, web search became unavailable, and the forum's public JSON endpoints served as a fallback for cross-checks.

A second pass filled gaps. It established that a desktop `mcp.json` URL server is called from the user's machine (documented indirectly through release notes), that cloud agents and self-hosted workers read MCP servers only from the dashboard configuration and not from a repository's `.cursor/mcp.json` (a staff forum statement that matches the pool docs), and that MCP behavior in Remote Control sessions remains undocumented. No official changelog statement about the removal of the old Memories feature was found; a dated staff forum post remains the best source. The session was then finalized with cursor-expert as the only participant: reflection produced two topics, a merge subagent integrated both, and the lore map validated at full coverage.

Open threads: the per-surface component support table, a "same setup on every device" recipe, and marketplace publishing details could still be deepened to match claude-expert's equivalents. Every Lore compatibility verdict is untested; the suggested first tests are a Remote Control hand-off of a booted Lore session and a My Machines worker started in the workspace. The SSE-in-cloud conflict and Remote Control MCP behavior need a live check, and plan facts need a recheck as The X Subscription rolls out.
