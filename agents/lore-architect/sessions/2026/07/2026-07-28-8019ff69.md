# Measured Cursor boot context cost

The session opened with a Cursor boot of lore-architect, then a direct comparison of Cursor's Context Usage UI before and after boot. Before boot the session sat at ~22.1K / 256K (9%); after boot it reached ~48.7K (19%). All of the growth was in Conversation (~192 → ~26.7K); fixed overhead (tools, rules, skills, MCP) did not move.

The user asked which docs the boot procedure had actually read, then had the agent count those files with `lore-framework/scripts/token-count` (`tiktoken` / `o200k_base`, via a temporary venv because macOS Homebrew Python is PEP 668). The seven boot files totaled 22,960 tokens. That was close to but not equal to the ~26.5K conversation delta — the gap of ~3.5K covered tool wrappers, MCP schema, the boot reply, and a 384-token preflight JSON.

Follow-up questions narrowed the picture: boot consumed ~10% of the 256K window; without `version-check.md` (the skew path taken because the repo was at 33 and the plugin at 32) the cost fell to roughly ~19K files / ~23K conversation (~9% of the window). The agreed rule of thumb was that a regular version-match boot costs around 20K tokens. `lore-context.md` was the largest single file (~9K); `agent-boot.md`, the Cursor engine profile, `role.md`, and (when triggered) `version-check.md` each sat in the 3–4K band.

Finalization recorded the measurement as `cursor-boot-context-cost-measurement.md`, linked it from `lore-context.md`, `agent-boot-doc-grew-when-scripted.md`, and `cursor-engine-capabilities.md`, and left the A8 `agent-boot.md` subtraction work as the main framework-side lever already queued.

Next steps remain the standing A8 subtraction pass on `agent-boot.md` and any agent-local compaction of `lore-context.md` if boot cost becomes a recurring constraint; no framework ship was attempted in this session.
