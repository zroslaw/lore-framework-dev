# Added learning audits to session summaries

The session opened with the user asking for a small, reviewable way to monitor how a Lore agent
learned during finalization: what reflection considered important, what merge changed or simplified,
and what ultimately reached durable Lore. The user deliberately kept the scope lean, preferring a
few procedure changes and one real Codex finalization lifecycle over a quality run or a multi-engine
matrix.

The implementation established an explicit evidence chain. Finalize now retains each agent's
current-session Reflection outcome and passes its topic paths into merge; merge returns concrete
learned facts, destination paths, semantic actions, residuals, and anomalies; summarize renders
those outcomes as a mandatory per-agent `## Learning` section. The contract distinguishes
completed-zero, failed, unavailable, and carried-over evidence so missing or old reflections cannot
masquerade as learning from the current session. A small Cursor adapter alignment and a closed-kind
mapping for guest frontmatter kept the cross-engine and guest-summary contracts coherent.

The main plot twist came from executing the prose. The first full Codex lifecycle produced the new
section but generalized the monitoring-tool fact into a category and dropped the concrete canary.
The procedure and tests were tightened to require the actual durable fact or decision plus its
reason. Focused reviewers then exposed further truthfulness seams around missing phase handoffs,
merge anomalies, guest action normalization, and carried-over attribution; those findings were
applied, and the final attribution verification returned clean.

The shipped tree passed 435 deterministic tests, with 48 expected real-engine skips, and one scoped
Codex `gpt-5.4` finalization lifecycle in 350.569 seconds. Quality and Claude/Cursor lifecycle runs
were not performed by explicit user direction, so no broader execution-fidelity claim was made.
Framework commit `33f312a` and tag `lr--v1.40.0` were pushed, along with dev-test commit `3aede05`;
the local Codex install was refreshed from the production v40 checkout.

Finalization then folded the session's two reflection topics into existing summary, finalization,
merge, lifecycle-testing, and versioning lore rather than creating parallel topics. It also updated
compact routing in `lore-context.md`, reconciled the repo stamp to v40, and raised v1 Lore coverage
from 15.2% to 16.9%. No product work or learning topic remained unresolved; the intentionally
omitted engine and quality gates remain recorded scope boundaries rather than hidden claims.

## Learning

### lore-architect

- **What mattered:** Canonical host summaries need an evidence-backed per-agent Learning audit whose retained Reflection outcome and structured Merge handoff prevent missing, failed, or carried-over evidence from being mislabeled as current learning. The real Codex lifecycle also showed that heading-level checks are insufficient: the audit must preserve the concrete learned fact or decision and its useful reason.
- **Lore changes:** Consolidated the audit schema and provenance rules in `lore/session-summaries-feature.md`; updated `lore/finalization-process.md` and `lore/merge-in-booted-subagents.md` with phase-evidence and structured-handoff obligations; updated `lore/lifecycle-testing-harness.md` with the concrete-canary assertion lesson; added the v40 ship record to `lore/versioning-release-types.md`; and updated `lore-context.md` with compact routing and current v40 state.
