# Tested how named and unnamed subagents differ and talk

The session opened with a question from the user: does creating a named subagent in Claude always create an Agent Team, so that a subagent can run only unnamed? The agent first answered from the tool schema that naming only made an agent addressable, and that the `team_name` parameter was ignored.

A run of small live tests overturned that answer. A named subagent came back with a `name@session` ID, appeared under Teammates in `ListAgents`, and reported through idle notifications. An unnamed one launched as a plain background agent, was listed only while running, and reported through a completion notification. The user then asked for more variants: a named subagent with an explicit agent type, an unnamed subagent resumed on a schedule, and a request for a subagent to run its own cron job. The subagent had no `CronCreate` tool, so a session cron job could only wake it by messaging it. Keeping unnamed subagents visible in the panel took several tries: the `lr-wait` sleep tool allows one wait at a time, `Bash` blocks a standalone `sleep`, and a `Monitor` that waits for a file worked.

Docs reading explained the observed difference: with the Agent Teams flag on, an `Agent` call with a `name` launches a teammate; with it off, it is a plain subagent. The user's settings had the flag on, so the agent changed it to off at their request and a named test subagent then launched as a plain subagent, with no restart. Two corrections came out of the research: idle teammate rows hide after 30 seconds rather than staying forever, and an earlier lore claim that siblings cannot be found was wrong.

Two full messaging tests, one with teams on and one with teams off, covered named and unnamed senders and receivers, idle and busy receivers, and messages to `main`. With teams off every pair worked. With teams on, a teammate could not reach an unnamed subagent by ID ("No transcript found"). A discovery test showed that subagents find named agents through a roster in their context at start, never through `ListAgents`, and that unnamed agents are reachable only by ID.

The session ended with all findings merged into the agent's lore: the older subagent topic became an area hub with three new children. Whether a resume refreshes the roster, and why one teammate lacked `SendMessage`, stayed untested. The test agents were stopped earlier; the five from the last tests were left idle.

## Learning

### claude-expert

- **What mattered:** The `name` parameter plus the Agent Teams flag decide whether an agent is a teammate or a plain subagent; subagents discover named agents through a start-time roster and unnamed ones only by ID; with teams on, teammates cannot reach unnamed subagents by ID; idle unnamed subagents are unlisted but resumable, and a `Monitor` on a file keeps one running.
