# Reviewed and shipped framework v36 (Lore structure and grooming)

The session opened with a request for a final, deep pre-ship review of the v36 release
candidate sitting on the `codex/lore-v1-implementation` worktree — a substantial release
introducing the Lore v1 file structure, deterministic maps, the `/lr:groom` skill, the
`lr_core/` package split, and automatic publication of framework updates, prepared in an
earlier Codex-driven session and deliberately left unpushed pending this review.

The architect read the full ~4,000-line diff first-person: the new `lore-structure.md`
contract, `groom.md`, every changed procedure doc, and all seven modules of the new
`scripts/lr_core/` package. Mechanical disciplines were verified (four manifests at
`1.36.0`, Cursor wrapper parity, cache-clear footers, migration 36's `(none)` write paths
against check #20, the `versioning-release-types.md` backfill), the 315-test deterministic
suite was re-run green against the exact final tree, and the new `lore-map`/`lore-workset`
commands were exercised live against the real 220-file corpus plus a synthetic v1 fixture.
The review found no correctness defects — only three doc-level findings: the release-notes
boot-footprint figures were codex-profile-specific without saying so, a misplaced paragraph
in `attach.md`, and a wrong finding name in `check.md` #11.

One review thread resolved a puzzle: the recorded 7,525-token system-prompt estimate did not
reproduce under the claude profile (6,234); measuring all three engines showed the record
was taken under codex, which became both a fix and a new lore rule (measurement records name
their environment). The review also surfaced honestly-recorded gate gaps: TriLens had ended
at its three-round cap without a clean-round attestation, and the real-engine lifecycle
suite had been deliberately excluded.

The user then directed: apply the fixes and ship, with real-engine lifecycle explicitly
waived. The three fixes were amended into the release commit (`1cda4cd` → `e5e097b`),
framework `main` was fast-forwarded and pushed, and tag `lr--v1.36.0` was created —
resuming a tagging practice that had silently lapsed for v32–v35. The dev repo branch was
landed with a ship-record commit updating the v36 history entry (final hash, tag, waiver as
record) and stamping `lore-repo.md` straight to "36", superseding a stale uncommitted "35"
edit. All work-tree cleanup followed: five worktrees removed, five local and two remote
`codex/*` branches deleted (the chronicler's unmerged v34-stamp branch was redundant with an
uncommitted edit on its main, which was left to the Keeper), and eight superseded
`draft-lore-*.md` workdir files deleted.

Finalization integrated four reflections. The merge subagent performed the repo's first lazy
v1 migration — `lore-context.md` gained v1 context frontmatter, two edited topics gained v1
metadata, and two new v1 topics were created (`gate-waiver-is-a-record.md`,
`measurement-records-name-their-environment.md`) — bringing structure coverage from 0% to
2.3% and making the v1 context-size warning visible (11,565 tokens against the 10K target).

Open threads: the lore-context size warning calls for a `/lr:groom` demotion pass; the
agent-boot.md subtraction pass (A8) remains queued for v37; the v32–v35 tag gap is recorded
but not backfilled; and the corpus-wide v1 conversion remains available via explicit
Whole-Lore grooming whenever the user wants it.
