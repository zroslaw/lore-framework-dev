# Created claude-expert and seeded its Claude product knowledge

The session started as a research conversation under another agent. The user wanted to know how Claude can be customized outside Claude Code: whether the Claude Code model of marketplaces, plugins, and skills also exists for ordinary Claude users, what the Customize page in the desktop app and the "Connectors directory" in the mobile app are, and how to get the same setup on mobile and desktop. The user asked for answers in ASD-STE100 Simplified Technical English for the session.

The research used Anthropic's public documentation (claude.com/docs, code.claude.com/docs, platform.claude.com/docs, the help center, and its release notes) and the pricing page. It established that connectors, skills, and plugins are installed on the account from Customize, sync one way to Claude Code, and are usable in chat on web, desktop, and mobile. It also established that chat ignores plugin agents, hooks, and local MCP servers, and that the mobile app has no Customize page and only browses connectors (adding them on mobile is in beta). Short follow-ups covered what a connector is (a registered MCP server plus the user's sign-in), the difference between chat, Cowork, Dispatch, Claude Code Remote Control, and cloud sessions, where subagents can run from a phone, how Claude memory and chat search work, and how the Pro, Team, and Enterprise plans differ.

Several points were corrected or left open along the way. Two help-center pages disagree about adding connectors on mobile, and the newer one was taken as authoritative. The user's first model of Dispatch as a separate laptop app was corrected: it is a manager-agent feature inside Claude Desktop that starts Cowork and Code sessions on the computer. Anthropic does not document whether memory topics are injected into every chat or retrieved, so that stays open. Some answers were labeled as inference, notably that Code-tab cloud sessions run subagents and that the `lr` plugin cannot run its scripts in the chat sandbox.

The user then decided to create a dedicated Claude product expert agent in this repository, with Codex and Cursor experts to follow later. `claude-expert` was created and registered (shortcut `lr-claude-expert-agent`), additional research on the current model lineup and the product map was added, and the session was finalized with `claude-expert` as host. Only public product facts went into this agent; the guest's private knowledge stayed in its own repository, where it now keeps only the basics and a reference to `claude-expert`.

Open threads: test whether the `lr` plugin can run in a local Cowork session, check what the Claude app exposes when asked to list its tools and in-context memory, and refresh the plan and model facts as Anthropic changes them. The workspace registration files (the shortcut and the AGENTS.md agent list) were published with `/lr:workspace-push`.

## Learning

### claude-expert

- **What mattered:** Where a session runs decides what it can reach: chat on web, desktop, and mobile runs in Anthropic's sandbox and cannot change local files; local Cowork, Claude Code, Dispatch, and Remote Control run on the user's machine; cloud Cowork and Claude Code cloud sessions run on Anthropic's servers, and Dispatch is a Claude Desktop feature, not an app. Plugin installs sync one way (Customize → every surface and Claude Code; CLI installs stay local), and components differ per surface (chat ignores agents, hooks, and local MCP; a top-level `bin/` blocks chat and Cowork). The `lr` plugin needs local `python3`, `git`, and the workspace repos, so it can run in Claude Code, probably in local Cowork, and not in chat or mobile chat (untested inference; test in local Cowork first).
- **Lore changes:** Replaced the minimal root `lore-context.md` with working knowledge (fact-checking rules, primary sources, evidence labels, product map, surface model, public-repo boundary); created four areas, `lore/claude-apps-and-surfaces.md`, `lore/extension-platform.md`, `lore/memory-and-personalization.md`, and `lore/plans-and-models.md`, with nine leaf topics under them, plus the root topic `lore/lore-compatibility-on-claude-surfaces.md` (inference, untested).
