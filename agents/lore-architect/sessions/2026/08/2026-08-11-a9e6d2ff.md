# Designed transcript-backed finalization MVP

The session opened with the user identifying a correctness problem in long Lore sessions: repeated
context compaction can remove early decisions and discoveries before end-of-session reflection. The
proposed remedy was to locate the engine-native transcript, split it into digestible portions, let
separate subagents reflect over each portion, and feed their results into the existing merge phase.
The first design confirmed that the substrate already exists across Claude, Codex, and Cursor in
`scripts/session-takeover`, and reframed the feature as a new reflection evidence source rather than
a second finalization lifecycle.

The user then pushed for a leaner implementation. The design contracted to an opt-in
`finalize --transcript` MVP for host-only sessions: reuse the takeover parser and bounded tool
summaries, split normalized main-thread dialogue at conversation boundaries, run cold read-only
reflection workers, mechanically collect their candidate topics, and rejoin the unchanged
merge/summarize/commit/push path. Compaction counting, automatic activation, guests, sidechains,
raw tool-evidence policies, transcript-backed summaries, and resumability were explicitly deferred.

An implementation-oriented design was written to
`workdir/draft-transcript-backed-finalization.md`. It specifies the CLI additions, verified current-
session marker, internal chunk manifest, workspace `.tmp` handling, worker brief and output
contract, bounded concurrency and context budgets, failure matrix, cross-engine expectations,
security boundary, deterministic and lifecycle tests, implementation commits, and acceptance
criteria. No framework implementation was started; the file remains a review draft.

Three consecutive Terra reviewers examined successive revisions, and their warranted findings were
applied after each pass. They removed semantic reduction before merge, bounded worker fan-out,
corrected merge identity wording, required Codex workers to inherit no turns, moved scratch data to
workspace-readable ignored storage, specified atomic writes and exact cleanup, tightened candidate
validation and overflow behavior, made the literal marker searchable in Cursor tool arguments,
narrowed the fidelity promise to parser-retained normalized dialogue, and added transcript-specific
privacy and aggregate-host-budget rules. A fourth Terra review was feedback-only, as requested, and
the draft was not edited afterward.

The final review assessed implementation readiness at 68%. It left four questions for the later
review session: overlap can itself push a rendered chunk beyond the size bound; read-only worker
isolation is a procedural promise rather than a technically enforced sandbox; the candidate result
format lacks a formal machine grammar; and sensitive-data exclusion still relies on model judgment.
Finalization preserved the design and review state in a focused Lore topic and routed it from
`lore-context.md`. The next step is to classify those four findings as ship blockers or explicitly
accepted MVP limitations before implementing the first deterministic transcript-preparation commit.
