# Verified v44 by real-engine gate, then drafted v45 boot announcements

The session opened immediately after v44 shipped, with the user asking to remove the now-merged
v44 branch and worktree. That turned into a broader audit: the user next asked whether the boot
procedure itself had been executed correctly. Checking it against `agent-boot.md` rather than from
memory found the boot substantively correct — right agent, right framework tree, both files read in
full, all eight report numbers correctly derived — but the report padded with four status lines that
Step 2 explicitly says to suppress. The doc even states the reason inline. That deviation turned out
to prefigure the session's main theme.

Asked what to fix next, the standing improvement list named A9 ("lifecycle runner reports false
greens") as top of tier A. Verifying before executing showed two of its three claims were false:
`run_matrix.py` returns 2 on refusal and 1 on failed modules, and had been unchanged since v36, so
the original observation ran exactly that code. The real cause was the invocation — piping the
runner makes `$?` the pipe's last element. Acting on the entry as written would have "fixed" correct
code. Both the entry and its lore topic were rewritten, including at the two other sites that
restated the rule in `role.md` and `lore-context.md`.

The user then asked for a Claude and Codex lifecycle run. Codex's identity gate had been blocked on
this machine for weeks (backlog B10), but the cause was not the marketplace source as recorded — it
was an installed cache lagging at v43, and behind that a five-week-old v32 tree in
`~/.codex/.tmp/marketplaces/` that the identity precheck never enumerates. With both addressed,
Codex passed identity for the first time. The first run then produced a misleading 9/18: six Claude
modules had hit an account session limit mid-run (2.7s durations, `$0.0000`), making them
uninterpretable rather than failed, while an identity flap made the Codex arm untrustworthy
entirely. A clean re-run gave Claude 8/9 and Codex 6/9, with every failure explained as a named
flake, a `subprocess.TimeoutExpired`, or a real fidelity miss.

The session's central finding emerged from those failures. Three times in one day, across two
engines, an executor did the substantive work correctly and failed to produce the required literal
output: `test_style` dropped a mandatory `Style set:` confirmation while correctly applying the
style, `test_trilens_loop` emitted `**LENSES:**` against a prompt demanding exact lines, and the
morning's boot suppressed nothing it was told to suppress. `docs/style.md` already carries maximum
emphasis on its confirmation and lost anyway. That reframed v44's flagship feature: `## Step 0 —
Announce` shipped to 33 skills with no static check and — verified — no runtime assertion anywhere
that an announcement is ever emitted. Measured on real transcripts, Claude announces on boot 3/3 and
Codex does not at all.

Two plot twists corrected the record mid-session. A `test_lore_v1` failure looked like a v44
regression in the new `preflight --agent-dir` upward search, and was nearly filed as one; it cleared
under verified identity, having been a stale v32 plugin. Later, `/lr:finalize` printed a base
directory of `1.42.0` while boot had resolved `1.44.0` — two framework roots live in one session,
with all four orchestrated finalize docs differing between them, so finalization was run off the
installed 1.44.0 tree and the instance folded into existing lore.

Work landed on two local-only branches at the user's instruction. `v45-announcement-gate` carries
`test_09_boot_announces_before_working`, proven red against `lr--v1.43.0` and green live on Claude,
plus the A9 correction and a re-ranked tier. `v45-boot-announcements` carries a new **Operation
Notice** convention — a conditional sibling to the Step 0 announcement, fired only when a procedure
does something consequential the user did not ask for, and silent on no-ops by design — wired into
`version-check.md`, `agent-boot.md`, and `attach.md`. Deterministic tests pass 540/540. `VERSION`
stays at 44; nothing was pushed.

Open threads: the Codex announcement miss needs a decision (engine-profile guidance versus a
doc-structure fix, not more emphatic prose); A9's surviving third, A11's three flaky scenarios, and
a `/lr:check` item for Step 0 presence all remain; and the v45 branches await both more features and
a push.
