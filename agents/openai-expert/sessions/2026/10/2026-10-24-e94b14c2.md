# Tested nested Codex agent scheduling

The session continued an exploration of Codex multi-agent behavior. The user asked whether child agents could create their own descendants and how the system decides which workers are active when a hierarchy contains more runnable agents than the configured capacity.

The test built a five-level Luna chain: scout, analyst, verifier, executor, and leaf. The final child initially could not start because a pending older worker consumed a shared slot. After that worker was stopped, the fourth-level agent created the leaf successfully. This showed that the active-worker budget is shared across the entire tree rather than allocated separately at every level.

The resulting guidance distinguishes model choice from runtime scheduling. Agents choose when to request a child or resume a worker, while the harness enforces the total active-worker cap. The public documentation describes the tree-wide cap and allows descendants, but does not define a fairness or priority rule for an overloaded runnable set; coordinators should explicitly select the next worker.

The session closed by merging the hierarchy and scheduling lesson into `openai-expert` Lore. An unrelated `cursor-expert` reflection directory was present in the repository and was intentionally left untouched.
