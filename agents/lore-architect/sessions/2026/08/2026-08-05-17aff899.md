# Retired automatic session archives in v34

The session opened with a request to turn off Lore's automatic storage and push of full session transcripts. The decision was refined before implementation: preserve aggregate usage metadata and retain `session-takeover archive` as a dormant manual primitive, but remove its automatic connection to summarize and finalize. The user also asked for archive-related boot and lore-search guidance to be removed rather than reframed as legacy policy.

The implementation updated the v34 finalization and summarization procedures so they write summaries plus optional usage only. It removed archive paths and frontmatter from the automatic lifecycle, documented the retained command directly in its source as dormant, and added deterministic contract coverage that forbids a later reconnection. Existing committed archives and historical summary records were deliberately preserved.

Validation used the complete deterministic suite and an active-reference audit. Real-engine lifecycle tests and TriLens review were not run at the user's direction; the v34 release notes and version-history lore record that limitation explicitly. A non-existent `lr-core check` command was identified during validation and was not treated as a passing check.

The release was shipped and pushed as framework commit `30f8402` and framework-dev commit `005f7f7`. The temporary release worktrees and six merged local branches were removed afterward. Two pre-existing untracked `.obsidian` directories in the dev repository were intentionally left untouched.

Finalization merged the session's archive-retirement decision into the takeover, session-summary, and session-durability lore topics. Future automatic archive work now requires an explicit privacy, retention, and lifecycle design rather than reuse of the dormant command by default.
