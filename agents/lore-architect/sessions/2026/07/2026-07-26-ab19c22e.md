# Redesigned lr-core as a literate accelerator for v31

The session opened with the user booting `lore-architect` and asking what was sitting in the
already-parked `wip/lr-core-v31` branch — work from a prior, rougher 2026-07-25 session that had
built a deterministic substrate script (`scripts/lr-core`) for boot/attach/consult/recall/pull-lore
but stopped short of shipping. Over several rounds of drill-down questions — the TTL-cached
auto-pull mechanism, the `scan` topic-manifest subcommand, and the Script Fallback Contract that
governs what happens when an accelerator script fails — the user shifted into `plain-language`,
`dialogue`, and `follow-me` mode for a tighter, incremental back-and-forth, and the conversation
converged on a design gap: the Script Fallback Contract's "Accelerator" category kept the hand-
executable procedure in a separate prose doc from the script that ran it, which meant the fallback
could quietly drift out of sync with the code it was supposed to describe.

The user proposed a fix and asked for it explicitly: make `scripts/lr-core` the source of truth for
its own procedures by writing the procedure as instructional comments inside the script itself,
with docs thinned to pointers, and asked that the approach be named as a reusable framework
principle rather than treated as a one-off. Claude entered plan mode, ran two parallel research
passes (one reading `cmd_preflight`'s exact structure and comment density, one inventorying every
doc referencing the Script Fallback Contract with verbatim quotes), and wrote an eight-item
implementation plan that the user approved. Execution followed the plan closely: `scripts/lr-core`'s
module docstring and its `cmd_preflight`/`cmd_discover`/`cmd_scan` functions (plus the `pull_repo`,
`compare_versions`, `detect_teammate`, and `_resolve_agent` helpers) gained numbered, instruction-
shaped docstrings; `docs/conventions.md` redefined the Accelerator category as "literate" and named
the general pattern; `docs/agent-boot.md`'s Manual Boot Procedure and `docs/auto-pull.md`'s Steps
1-3 were thinned to pointers into the script (`auto-pull.md` dropped from 100 to 80 lines); the
fallback sentences in `attach.md`, `consult.md`, `lore-search.md`, `process-merge.md`, and
`pull-lore.md` were trimmed the same way; a new lore-architect topic,
`literate-accelerator-pattern.md`, was written directly into the worktree's lore (deliberately kept
out of the host's main lore, since the pattern's first instance is itself unshipped); and
`release-notes/31.md` was updated to match.

There were no major plot twists — the design direction was fully specified by the user before
implementation began, and every step was applied exactly as planned. The main discipline exercised
was verification: the full existing `tests/test_lr_core.py` suite (38 tests) passed unmodified
after the comment rewrite, a `py_compile` check and a live `preflight` invocation confirmed
identical behavior and JSON shape, and a grep sweep across both worktrees turned up no stale
"docs are normative" claims left over from before the flip.

Nothing was committed to the parked branch this session — per the plan, and consistent with how
the branch was already being held, the worktree edits stayed uncommitted for a later ship decision.
Finalization then ran against the host's main checkout only. Reflect wrote one topic capturing the
session's design change and its impact on the existing resume plan. Merge, run in a subagent booted
as `lore-architect`, extended the existing `v31-lr-core-parked-2026-07-25.md` topic in place (rather
than duplicating it) with a "2026-07-26 addendum" that explicitly flags today's new script/doc
surface as **not yet trilens-reviewed** — the prior "trilens round 3" resume step only covered the
round-2 correctness-fix delta, so round 3's scope needs widening before v31 ships. `lore-context.md`
was updated to match, and the reflections directory was cleaned up afterward.

What's still open: the parked branch's resume plan (now widened) still needs the two missing
round-2 regression tests, a trilens pass covering both the round-2 delta and today's literate-
accelerator rewrite, the full lifecycle suite, and only then a commit and push to ship v31. The
`literate-accelerator-pattern.md` topic will land in the host's main lore naturally once that
happens — until then it's parked, same as the rest of the branch.
