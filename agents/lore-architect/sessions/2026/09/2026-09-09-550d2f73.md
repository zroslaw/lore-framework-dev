# Shipped v45 after review found four blockers

The user asked for a thorough review of the v45 release candidate sitting in its worktree. The
review found the work sound and the release record not: the design of the unified `check` front
door held up, the code carried no correctness bug the review could find, but the framework
worktree was dirty with four uncommitted files, and those files carried three real defect fixes.
The tree under review was therefore not the tree that would have shipped, and no gate result
belonged to either state. That became the session's first finding and its first correction —
a release review starts with `git status`, not the diff.

Verification of the candidate's own claims followed. All four plugin manifests were confirmed at
`1.45.0`, the release-tag probe was exercised live against the upstream, and the deterministic
suite was re-measured rather than trusted: 343 tests against the candidate, against a
Verification section that claimed 342 and named only two of the three landed fixes. The three
uncommitted fixes were each proved genuine by rebuilding a pre-fix copy of the framework and
showing the corresponding tests red against it — including one that mattered more than its size
suggested, since a brand-new agent with no Lore files was reporting its whole health check
incomplete, which is exactly the state `/lr:create-agent` leaves behind.

Nine findings came out of the review. The user approved fixing four: commit the working tree,
correct the release notes' counts and missing entries, repair an `INSTALL-CLAUDE.md` sentence
that promised `/lr:check` would "heal" a stale plugin cache when tier-3 findings are display-only
by contract, and close a gap the release itself created. That last one became new work: a managed
`AGENTS.md` routing map keeps advertising skills an upgrade removed, every heading stays correct,
and the existing section-count checks were structurally blind to it. `memory_state` now reads the
command table and names any skill the framework no longer ships, answering `None` rather than an
empty list when `skills/` cannot be read. It fired immediately on this workspace, naming
`workspace-status`.

The user then declined the lifecycle suite and TriLens on cost, but asked whether the release
could break anything essential. Rather than shipping on assertion, the session ran a
blast-radius audit: it partitioned the change set to the twenty-nine files outside the check
surface, proved fifteen named essential docs and scripts byte-identical to v44, read all four
shared-code edits, and diffed the old and new `lr-core preflight` output on the real boot path,
which came back identical apart from the version number. That evidence, and an explicit statement
of what it does not cover, went into the ship record beside the waiver.

The ship itself was uneventful except for one hazard. Merging the three v45 branches, uncommitted
WIP on `lore-framework-dev` main collided with the incoming branch in two files. Rather than
stashing into a stack shared across worktrees, the session proved supersession by computation —
28 of 30 added backlog lines matched the branch version exactly, and the two that did not were
the branch's improved phrasings — backed both files up, and left every non-colliding dirty path
alone. Tag `lr--v1.45.0` landed at `f12765d`, both repos were pushed, all three worktrees were
removed, and the version history was backfilled with the real shipped facts in the same
finalization, per the standing discipline.

Five design findings shipped knowingly and were filed to the backlog rather than left in
scrollback: the Operation Notice convention contradicts its own first application, it is rendered
on only one of the two call paths it names, the default report's headline is drowned by 965
info-tier reference cautions, `check` is scanner-first where `doctor` was symptom-first, and
diagnosis lost its literate fallback. Two remote branches were left undeleted pending the user's
confirmation.

## Learning

### lore-architect (host)

- **What mattered:** When the user waives the expensive gates, a four-step blast-radius audit is
  the cheap substitute that bounds what the unrun gate could have caught — partition the change
  set by surface, prove the essential docs and scripts byte-unchanged by named path, read every
  shared-code edit (too many to read means the audit fails and the gate is not waivable), then
  A/B the essential path's real output. A release review starts with `git status` on every repo,
  because uncommitted fixes are the most invisible form of ungated work: a post-gate commit at
  least leaves a SHA, a dirty file leaves nothing and `git log` looks clean. When merge-time WIP
  collides with an incoming branch, prove supersession by computation rather than by eye, since
  blind `git stash` is unsafe in a workspace with concurrent sessions sharing one stash stack.
