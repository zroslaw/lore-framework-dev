# Created openai-expert and mapped OpenAI's products

The session created the first lore for `openai-expert`, a new agent in `lore-framework-dev` and the sibling of `claude-expert`. Its role was already written and its lore was empty. The task was to research OpenAI's products from the user's side and to give the agent at least the coverage that `claude-expert` has for Claude: the product family, the surfaces and what each can reach, the mobile app, the extension platform, remote MCP on each surface, memory and personalization, plans and pricing, models, Lore compatibility, and other features that an agent-framework designer should know.

The agent booted, studied all fourteen `claude-expert` lore files as the template, and then researched everything live, because the product set had changed a lot since its training data. The best sources were the Markdown twins and full-site exports on learn.chatgpt.com and developers.openai.com, which were downloaded once, split into one file per page, and searched locally; the Codex release list came from the GitHub API. The agent wrote a root context, four areas (apps and surfaces, extension platform, memory and personalization, plans and models), and focused topics under them, with a check date, a source, and a label (documented, third-party report, or inference) on each fact. A second pass compared the lore with the `claude-expert` files again and added topics for apps and connectors and for plugin install and per-surface component support, plus chat search, Enterprise-only features, and data-training notes.

Several findings changed the expected picture. The standalone Codex app merged into the ChatGPT desktop app in July 2026. ChatGPT now has three modes (Chat, ChatGPT Work, Codex) and an always-on agent called a dot. Plugins in one shared directory replaced connectors and are replacing custom GPTs, and "developer mode" became an "Add custom MCP server" flow on the Plugins page. The help center and the pricing pages refused automated fetches, so their facts came only from search snippets, and one snippet turned out to describe an older version of a developer page. Three questions stayed open after two research passes: which plans can add a custom MCP server in ChatGPT, whether Codex Cloud tasks can use MCP servers, and whether ChatGPT or Codex use MCP prompts.

Finalization ran with `openai-expert` as the only participant. The merge subagent finished its integration and validation but was stopped by an API rate limit during cleanup, so it returned no handoff; the host checked the disk (reflections removed, Lore map complete with no findings) and reconstructed the merge handoff below from the files. The usage block covers this agent's own transcript only, not the merge subagent's. The lore ends with 24 topic and area files, complete map coverage, a helper script in the agent's workdir that splits a docs export into pages, and the open questions collected in one topic. Facts about Lore itself on OpenAI surfaces stay labeled as untested inference.

Next steps: verify custom MCP plan gating in a browser, test a custom MCP plugin from the ChatGPT mobile app, test the `lr` plugin in Codex inside the ChatGPT desktop app, and tell `lore-architect` that `codex mcp-server` was removed, because some of its notes still mention it.
