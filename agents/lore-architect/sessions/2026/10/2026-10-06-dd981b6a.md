# Switched framework license to MIT-0 and back

The session booted the lore-architect and then turned to a licensing question. The user wanted to temporarily move the framework from MIT to MIT-0 so that some people could clone and use the source without attribution, and asked whether an owner can do that. The answer given was yes for code the owner holds copyright on, with caveats: contributors' code needs their consent, vendored third-party code keeps its own license, and anyone who receives the code under MIT-0 keeps those rights permanently, so the change cannot truly be temporary. A per-person written permission was offered as a narrower alternative.

The user chose the full switch and asked for it to be pushed without changing the framework version. The architect found six places that state the license: `LICENSE`, the `license` field in the four plugin manifests, `MARKETPLACE.md` and `README.md`. All were changed in one commit (`170b9b9`), and `VERSION` stayed at 47.

Before pushing, a check of `git shortlog` showed a second author with a substantial commit, the spawn-teammate feature. The push was held and the user was asked. They clarified that the second identity was their own and that the other person had agreed, so the commit was pushed. Shortly afterwards the user asked to revert to MIT. A plain `git revert` was pushed as a new commit (`cbf1c0c`), leaving published history intact and `LICENSE` and all manifests reading MIT again.

The session's plot twist was the authorship question: an apparent outside contributor turned out to be the user under another git identity, which is why the check was framed as asking rather than assuming. The dispatched finalize skill also resolved to the 1.46.0 plugin cache while the boot used 1.47.0; the dispatched docs were followed. The session ended with the framework back on MIT and nothing pending. Anyone who cloned during the short MIT-0 window keeps MIT-0 rights to that snapshot.

## Learning

### lore-architect

- **What mattered:** A license change touches six sites that must move together, is not a framework release (no VERSION bump, migration or notes), and the push is the irreversible step.
