# Five consecutive lore grooming runs, measured

The session opened by booting the lore-architect and running `/lr:groom` once, which reviewed five recently changed files, corrected stale "release candidate" wording around the shipped v47 participant revision, added v1 frontmatter to `worktree-lifecycle-and-audit.md`, and kept the lore-context pointer to the shipped feature small. The user then asked for five grooming runs in a row, with metrics measured after each, a report kept in the agent's workdir, and the session finalized afterward.

A metrics script was built first (`workdir/grooming-exercise/measure.py`) tracking mapped-file and token coverage, legacy count, lore-context, boot-map and boot-footprint tokens, root fan-out, hub count and validation issues. Run 1 split the 21k-token `versioning-release-types.md` into an area hub and three lossless history children, verified line by line. Run 2 converted 17 legacy topics to v1 while correcting stale statements (a VERSION "currently 12", "nothing shipped yet" for Lore Beings, a `workspace-sync` naming mix-up). Run 3 moved the "Operating Disciplines" rule bodies out of `lore-context.md` verbatim into four new area hubs and re-parented about 85 flat topics under them. Run 4 repaired stale `workspace-status` references and history links. Run 5 converted the 30 smallest remaining legacy topics.

The main surprise was procedural: `lore-workset` ranks every uncommitted file first and grooming never commits, so by Run 4 the "recently changed" tier alone exceeded a 90,000-token budget and the rotation tier that reaches unreviewed lore returned nothing. The budget was raised openly and later runs used hand-chosen slices, which the report records as deviations. A smaller correction came mid-run when a child topic's `parent:` had to be the `lore/`-prefixed path, and a metrics file was accidentally truncated and had to be rebuilt from known values.

The runs ended with mapped files at 60.2% (from 42.0%), legacy files down from 178 to 125, `lore-context.md` at 7.3k tokens (from 10.1k), the boot map halved, and a per-session boot footprint 19% lower, with zero validation issues. Total lore tokens rose about 2% from hub overhead. All changes are uncommitted until this finalization. The report is `workdir/grooming-exercise/report.md`.

Open threads: split `parallel-reviewer-fanout-pattern.md` and `lifecycle-testing-harness.md` once their inbound `§` citations are repaired, point per-version citations at the exact history child, update `role.md`'s backfill instruction (outside the lore write set), and convert the remaining 125 legacy files; the default groom needs an "already reviewed SHA" exclusion to be useful on an uncommitted tree.
