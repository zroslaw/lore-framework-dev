# Collapsed v46 into one ship after a deep review returned three blockers

The session opened with a status question about v46 and was answered from the repo rather than from
loaded context: `VERSION` still read 45, `lore-framework` sat two `.gitignore` commits past
`lr--v1.45.0` with no tag at `HEAD`, and no v46 branch, worktree or implementation existed anywhere
on disk. The lore-sync-hardening work was design-complete in parts and deliberately held — a
decision taken earlier the same day that nothing ship until Tier B was designed to completion and
Tier C decided.

The first substantive finding was a contradiction between the agent's own artifacts. The standing
improvement list still named "implement Tier A" as the next action while the lore topic carried the
later hold. The list was corrected, and then the question of what "design Tier B to completion"
actually meant was worked through. It surfaced that Tier B was not a clean subset: the Ours/Foreign
conflict classification at § 4 Step 4a had been filed under Tier C, but that classification *is* the
merge-retry rule, and without it `publish-lore.md` has no defined behaviour on a conflicted merge —
collapsing `merge-retry` mode into the stop-on-any-conflict design § 3 had already rejected, because
`lore-context.md` is rewritten by every finalize and is the system's most frequent collision. The
user approved moving it into Tier B and, separately, chose report-only handling for the stranded
marker. Tier B design was then completed across five items: C7 moved in whole, a Tier B test set, a
Tier B rollout, and the two open questions that touched it. Four contradictions the B-before-A
reorder had created were found and fixed in place — the most consequential being Tier A's rollout
section still claiming v46 for itself and assigning v47 to Tier B.

The deep unconstrained cold reviewer that the non-convergence rule prescribes was then run against a
frozen tree, cold context, with an explicit instruction to verify the spec's claims about other
framework files against those files rather than trust them. It returned **BLOCK** with thirteen
findings: three BLOCKER, five HIGH, four MEDIUM, one LOW. Nine prior reviewer passes had found none
of them, and every one of the three blockers was a claim about a neighbouring document that had
drifted or was never true. The rollback rule reset to `HEAD^`, which stops being this operation's
commit once Step 4a creates a merge commit — producing the exact ratchet I5 exists to prevent. The
failure-classification table had no row for a plain non-fast-forward rejection, which is the only
way the update path can fail at all. And C3 cancelled its own fix: `update.md` states the zero-ahead
condition in three places, and the spec removed one while explicitly preserving another. Two
findings were spot-verified against `update.md` and `workspace-init.md` before any were relayed as
fact; the rest were verified before being applied.

The user then withdrew the tiering entirely. All ten changes ship as one v46 — there is no v47 and
no staged rollout — with more scope to be added in later sessions. The reorganisation that followed
was substantial: a new § 0 ship map that explicitly wins over every section contradicting it, the
marker restored from report-only to full form, C4 restored from bare to marker-aware, the per-tier
test sets and rollout sections withdrawn with their still-valid content folded into the shared ones,
and § 14a marked as history rather than plan. Tier vocabulary was kept throughout as review record,
because it is what makes the seven-round provenance legible.

All thirteen findings were applied, eleven new tests (T34–T44) were specified for them, and two
further leftovers were caught on a final sweep: a `findings-catalog.md` row still handing users the
`merge && push` remedy the spec calls unsafe three sections earlier, and a severity paragraph still
reasoning about a marker it assumed absent. The spec now records two gates outstanding before
implementation — a pass over round 7's own amendments, and a first review of the marker cluster,
which no round has examined as shipping work.

## Learning

### lore-architect (host)

- **What mattered:** A stalled review loop is fixed by changing the *instrument*, not the lens — the
  round-7 reviewer found three blockers nine lens passes missed because its brief licensed it to
  distrust the spec's claims about other files and go read them. A relative git ref (`HEAD^`) in a
  procedure silently retargets once an intermediate step moves `HEAD`, so a rollback must record an
  absolute sha and refuse to reset across a merge commit. A failure-classification table must be
  enumerated from the procedure's own exit paths, not from the cases the design happened to discuss,
  because an executing model handed an unlisted outcome guesses. And a tiering whose seams keep
  generating findings in consecutive rounds should be collapsed rather than re-cut.
- **Lore changes:** Merge ran in a separate session at the user's direction after this session's
  merge subagent was terminated by a session rate limit, so **no merge handoff reached this
  session**. The resulting changes are recorded in `lore-framework-dev` commit `ebaed0f`: created
  `lore/review-grounding-beats-lens-novelty.md`,
  `lore/relative-git-refs-retarget-when-a-procedure-moves-head.md` and
  `lore/classification-tables-enumerate-exit-paths-not-interesting-cases.md`; updated
  `lore/tiering-a-reviewed-spec-creates-unreviewed-seams.md` (absorbing the fourth reflection rather
  than creating a fifth topic), `lore/v46-sync-hardening-tiered-plan.md`,
  `lore/a-detection-tier-must-outlive-the-cure-it-measures.md`,
  `lore/a-state-file-is-a-hint-not-a-verdict.md` and `lore-context.md`. These file actions are read
  from that commit, not from a handoff.
- **Not merged:** None. The `reflections/` directory is absent and the tree is clean.
- **Issues:** The merge subagent spawned by this session failed with an API rate limit
