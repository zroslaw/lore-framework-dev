# Rewrote the v31 trilens-loop doc and dogfooded it on itself

The session opened on the parked v31 `lr-core` branch, with the user asking to revise
`docs/trilens-loop.md` so that it read as generic procedure rather than a description of one
particular review, and so that it said explicitly that both the parent session and its reviewers
should stay lean in tokens and in the data they exchange. The doc at that point was the deliberately
compressed one-paragraph version cut on 2026-07-25 — a compression the agent's own lore forbids
restoring unasked — so every expansion during this session had to come from the user rather than from
the agent's judgement about what had been lost.

The revision proceeded in small user-directed increments across roughly a dozen turns. Structure
replaced the prose block: a numbered loop, stopping rules, an exchange contract, and overrides. The
count of three lenses came back as the explicit default at the user's insistence, since differing
perspectives are the point of the skill, and lens *choice* was written as the host's own
responsibility, reasoned from what actually changed. The exchange contract was the session's main new
idea — the host sends a reviewer only the trees, the changed-file list, a sentence or two of
orientation, and its lens; the reviewer discovers the changes itself and returns only findings as
pointers into existing files, each with a paragraph and a severity. Later turns added a compact
severity/verdict/disposition vocabulary, a hard three-round ceiling, a short reporting step, and a
regular-model-tier rule naming sonnet, composer-2.5, and gpt-5.4 as illustrations rather than a
lookup table.

Two corrections mid-session came from the user rather than the agent. The first: the agent had
carried an open deferral saying `docs/engines/cursor.md` pointed at a rule the compressed doc no
longer stated, and the user pointed out that Cursor does have a native subagent mechanism, recorded
in lore since the v30 profile correction — `Task`, shipped in Cursor 2.4. The agent verified this,
corrected the profile's closing notes, which still described Cursor's subagents as unverified claims,
and added the caveat that a green lifecycle run does not prove which tool dispatched the reviewers,
since scenarios 28–29 assert only lenses and file edits. The second correction was about delivery
rather than content: after a long analytical answer to a short question about token cost, the user
invoked `/lr:plain-language`, `/lr:dialogue`, and `/lr:follow-me` together.

The plot twist was the dogfood round. The user asked for the trilens loop to be run on the session's
own changes, and the agent ran it against the doc it had just written: three cold sonnet reviewers on
hand-executor fidelity, internal consistency, and corpus coherence. The corpus lens returned a
verdict of `BLOCK` and it was right. It found that the agent's earlier reasoning — that the Cursor
deferral was moot because every Tier-1 engine now has subagents — contradicted Operational Rule 1 in
the agent's own `subagent-as-optimization-vs-subagent-as-semantics.md`, which requires a
semantics-class procedure to state its classification and its no-host-side-fallback rule *in the
doc*, independent of any engine's capabilities. The rule was verified by reading it rather than
recalling it, and the clause was added. The same round caught `release-notes/31.md` still describing
a single-paragraph doc that no longer existed, and a "don't go hunting through engine profiles"
sentence that two lenses independently flagged. Of 18 findings, 11 were applied, 5 declined as
deliberate host-judgement design, and 1 accepted without action — the regular-model-tier rail, which
the user then chose to restore, converting it to applied.

The loop's cost was measured rather than estimated: 174.1k tokens across the three reviewers against
roughly 10k on the host side, meaning about 94% of the spend stayed inside subagents. The two lenses
that mostly read the two changed files still spent 44k and 31k against maybe 4k of actual file
content, which showed that a reviewer's budget is dominated by its own reasoning and that the
no-diff rule is close to cost-neutral. That reframed the exchange contract: its real value is
reviewer independence and host-context preservation, not token savings.

Work landed committed on `wip/lr-core-v31` in both repos at the user's explicit instruction —
`c3d418d` in `lore-framework` and `8fc46f0` in `lore-framework-dev` — with the branch deliberately
not merged to main and not pushed, so the work continues next session. The lifecycle suite has still
not been run against this state and remains the single outstanding pre-ship gate. Two smaller threads
stay open: the Codex reviewer model is named gpt-5.4 in the doc but gpt-4.5 in the shipped v30
release notes, left unreconciled because rewriting shipped notes would lose provenance; and the
regular-model-tier clause landed after the reviewers had run, so it is ungated by the round that
cleared everything around it.
